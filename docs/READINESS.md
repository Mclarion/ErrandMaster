## Offline acceptance before a live test

- With Lua 5.1 and `lupa` installed for development, run `python3 tests/run_tests.py` and `git diff --check`. The Lua 5.1 boot mock loads the actual TOC module list, but cannot validate native layout, secure APIs, or game-managed persistence.
- Run `python3 tests/benchmark_walk.py` and `python3 tests/benchmark_npcs.py`. Record the 400-node/200-stop and 20,000-NPC/1,000-service/200-errand timings; these are diagnostics, not hardware-independent thresholds.
- Verify the separate QuestieDB Forever package has addon folder `QuestieDB`, interface `16001`, contract `4`, and the expected API/area conversion before installation. Do not copy its NPC records into ErrandMaster. `/em npcs status` must disclose incompatible or incomplete provider coverage; no 100% spawn guarantee is implied.
- Verify schema 5 migration/default-off consent for both existing and new characters; corrupt trail storage must preserve the original data, warn, and disable recording without blocking errands. No recording may cross a character switch.
- Verify observed edges are directed and restricted to continuous grounded samples. No implied reverse traversal, terrain link, floor transition, or shortcut. Unknown elevation, ambiguous nearby nodes, unrecorded connectors, disconnected errands, and missing/secret native API values must yield partial or unknown paths. `/em next` must not navigate a partial/unknown path and must clear only its own stale TomTom handle.
- Keep the native quest waypoint/POI path contextual and ephemeral. Stale quest targets must defer; observed service positions are approximate player positions, never asserted NPC spawns. Suggested map levels are a preference penalty, not proof of safety.
- Build and read back a runtime-only archive from the TOC, bindings, documentation and icon files; no tests, local development dependencies, saved player data, secrets, or external dataset may be included. Install only the authorized test candidate after its public source and recovery checks pass. No outside NPC coordinate import without verified redistribution rights, provenance, build relevance, and a separate review.

## Rollback after a client test

The guarded installer retains the entire v0.6.1-rc1 addon tree, each existing `AddOns.txt`, and each existing `ErrandMaster.lua`/`ErrandMaster.lua.bak` under `Interface/ErrandMaster-backups`, outside active `AddOns`. It hashes the copies before changing the installation. Its failure path attempts to restore v0.6.1-rc1; if recovery fails, it leaves all backups and reports the error. Independent readback checks the saved copies and the unmodified pre-test save files by hash, without displaying their contents. The separately managed QuestieDB provider is never changed or removed by this upgrade or its rollback.

If WoW has loaded v0.6.2-dev, close it before reverting. Preserve newer saves separately; restore the v0.6.1-rc1 addon tree and, only if a compatibility issue requires it, the matching preinstall SavedVariables and `AddOns.txt` backups. Verify exact file hashes and the stopped process before relaunching. Reverting an older save discards errands recorded during the v0.6.2-dev test; keep both copies and choose deliberately. Leave QuestieDB alone. Do not inspect or modify SavedVariables while WoW runs.

1. Back up installed addon, addon-state files, and SavedVariables outside `AddOns`; verify the game is stopped, the target path/build, enabled-state files, archive contents, and installation readback. Do not overwrite a newer or unknown install. Preserve the v0.6.1-rc1 rollback and all older backups.

Only continuous ground segments may become directed edges; partial/unknown must remain labeled.
3. Test known/partial/unknown route order and level penalties against actual terrain. A recorded path does not guarantee repeatable safety or comprehensive traversability. Check route refresh responsiveness with many errands and recordings. Verify `/em next` and optional TomTom ownership, especially after a known route becomes partial/unknown.
4. Test QuestieDB load order, `/em npcs status`, name/subtitle search, class/profession trainer and vendor filters, nearest wheel labels, map `N` pins, `/em npc add <ID>`, and immediate route recalculation when queuing a wheel option. Confirm service observations and gossip POIs are approximate and correctly classified. Check different faction, phase, locale, map, and floor; do not claim a spawn is present or walkable based solely on the provider. Test an active quest with changing objectives and absent waypoints; verify native POIs.
5. Verify v0.6.2 wheel sectors against icon centers at seven and 24 slots, **Flip pie art** calibration only if direction is reversed, drag/drop/folders, key/mouse binding, cursor restoration, combat dismissal, icon rendering, scale and edge layout; minimap/list controls, map pins/coincident icons/Shift-click; persistence on both characters. Spell/item/macro entries must remain previews with no execution.
6. If a native API, persistence, security, or layout check fails, stop testing, preserve the backup and error details, and fix before stable promotion. A clearly labeled test candidate may be installed with the player's authorization before these checks; it is not a verified stable release.

## Known limitations and later work

- The 400-node per-character trail cap stops recording and warns rather than silently replacing accumulated evidence. `/em trails status` shows counts; `/em trails clear` requires a second confirmation and deletes the current character's observations. Long journeys require a separately designed, tested compaction/retention policy; do not silently prune user evidence.
- Ordinary manually entered pins usually lack trustworthy world elevation, so proximity to an observed node does not establish a fully known route. Keep these partial until a safe destination-evidence mechanism is proved live.
- Native APIs do not provide a complete NPC-coordinate catalog or terrain navmesh. QuestieDB is a runtime provider, not a bundled catalog; its coverage, licensing for any future redistribution, and exact Forever-build relevance have not been established in the live client. A map with more than 10,000 service records is explicitly labeled incomplete. Cross-map travel, boats, portals, hazards, enemy density and faction restrictions are not routed. Stop ordering is greedy, not globally optimal.

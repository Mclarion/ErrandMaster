# ErrandMaster – Smart Route Planner

An early, **source-only** WoW: Forever addon (v0.4.0 offline candidate). It stores personal errands, player-set map markers and selected active quests, then suggests an approximate same-map route. It includes opt-in player-discovered service locations, explicitly registered in-game gossip POIs, and a click-to-confirm radial selection wheel. It does **not** automate movement, interactions, combat, or purchases.

## Install and verify in game

1. Copy this `ErrandMaster` directory (excluding `.testdeps`, `.venv`, `tests`, `tools`, and `.gitignore`) to the **Forever** client `Interface/AddOns/ErrandMaster`, not the Retail or Classic Era client. Include `Bindings.xml` and `Textures/HiddenCursor.blp`; they are required runtime assets. The beta path observed in September 2026 was `World of Warcraft/_classic_beta_/Interface/AddOns/ErrandMaster`.
2. The Forever Beta `WowB.exe` file version was read remotely as **1.60.1.70374**. The previous **v0.3.0** source was published at `github.com/Mclarion/ErrandMaster` and installed with its files hash-matched; four existing addon-state files were enabled with backups. **This v0.4.0 candidate has not been published or installed there yet.** In the actual client, use `/dump select(2, GetBuildInfo())` for the build and `/dump select(4, GetBuildInfo())` for the interface. Compare the latter to `## Interface: 16001`. No live API assertion has been made for build 70374.
3. Enable the addon on the character selection AddOns screen and log in. If initialization fails, check chat and the game's Lua error display. Try `/em help`, `/em add`, then add an errand, `/em route`, `/em next`, and `/reload`.
4. Confirm an errand survives `/reload`, logout/login, and a full restart on the actual installed build. Persistence is unverified outside a Lua mock.

## Current features

- `/em` opens/closes the window; `/em add` focuses the name input. The window supports add, edit, delete, complete/reopen, move up/down, selected scope toggle, and current-position capture. Blank location fields create an unlocated task. Coordinates entered in the UI are **percent** (0–100); stored coordinates are normalized (0–1). No preloaded NPC catalog is included; destinations must be entered or observed.
- `/em route` lists the first ten same-map stops and a count of deferred errands; `/em optimize` enables automatic ordering; `/em next` reports the next name, map ID, coordinates and estimated direct yards where available, and optionally creates a TomTom waypoint. `/em settings` shows the window's order/scope/TomTom/discovery and Wheel settings controls; `/em debug` toggles a stored flag (detailed event tracing is not implemented); `/em help` lists commands.
- **Radial selection:** click **Wheel settings** in the main window (or `/em wheel settings`), then **Set wheel key** and press an unused keyboard key out of combat. `Bindings.xml` also exposes the action under WoW's AddOns Key Bindings as a fallback. `/em wheel` previews it without a binding. The wheel centers on the current mouse position; moving the mouse from the center highlights a slot. Left click on a category opens the Add errand form with that category prefilled, **without creating an errand until Add errand is clicked**. Left click in the center dead zone cancels; Escape and a non-left click also close it. Opening is refused in combat and entering combat closes it. Wheel radius, icon size and seven slot assignments persist in account-wide SavedVariables; the key is owned by WoW's binding system. Near an edge, some icons can be clipped. Hold-and-release selection is not implemented.
- **Wheel customization:** in Wheel settings, enter a slot number (1–7), type `category`, `spell` or `macro`, and a category name or numeric spell/macro ID; click **Assign slot**. The wheel displays validated native names/icons when available and falls back to the ID otherwise. **Selecting a spell or macro only reports its name and ID in chat; it never casts or executes it.** WoW's protected/secure action path would require separate design and in-client verification. A character-specific macro ID may mean something different on another character; check assignments there before relying on their labels.
- **World map:** `/em map` or **Map destinations** opens the native world map with ErrandMaster-owned, labeled same-map route markers (amber) and observed service positions (blue). The addon does not remove Blizzard or other addons' markers. **Shift-left-click** the map to add a character-scoped “Map errand” at that position; rename it in the main window. A six-row paged map-quest list selects a quest with an available native POI; `/em quests` lists up to ten current-map candidates and `/em quest <ID>` selects one. Only quests in the active log with validated same-map POIs can be selected. If a quest's POI disappears or leaves the current map, its errand is deferred rather than routed using stale saved coordinates. No cross-map walking route is inferred.
- **Distance:** `C_Map.GetMapWorldSize` supplies map width/height in yards when supported and nonsecret. The planner uses those dimensions in same-map nearest-neighbor ordering and shows each leg plus the total as **estimated straight-line yards, not walking distance or travel time**. When that API or the player's position is unavailable, yards are not shown; normalized-coordinate ordering remains a fallback. Terrain, obstacles, transports, and inaccessible places are not modeled.
- While the wheel is open, `SetCursor` attempts to use the packaged transparent BLP texture; closing, Escape, and combat restore the default cursor. If the client does not support that cursor API/texture, the wheel remains clickable but the cursor may remain visible. The texture and all keyboard/mouse/visual behavior need an actual client test; no mock can establish that a cursor truly disappears on build 70374.
- **Opt-in discovery:** `/em discover on` or the window button records the player's **approximate position** when the native merchant, mail, or auction interface opens. `CanMerchantRepair()` must return true to add Repair alongside Vendor. No services are recorded at first install or migrated from older saves unless the player enables this. `/em discover off` stops automatic observations. Bank and trainer event capture await build-specific verification.
- **Game POIs:** after a player obtains a marker through in-game gossip, `/em poi repair` (or another explicitly chosen category, such as `bank`, `mailbox`, `auction house`, `vendor`) attempts to save the map coordinate returned by `C_GossipInfo.GetPoiForUiMapID` and `GetPoiInfo`. The addon **does not classify the POI**; the category is the player's assertion. This explicit command works with passive discovery off. No marker/API, protected value, or invalid coordinates means no record. The POI name is a map label, not a verified NPC identity.
- `/em locations` lists the first ten observed locations with IDs, coordinates and precision; `/em forget loc-<number>` removes one from the current character's registry. Records are character-only to avoid silently assuming another character can use the same service. There are no fabricated NPC IDs. Unlocated errands with a matching category can be routed to the nearest previously observed same-map candidate; directly entered errand coordinates always take precedence. Approximate locations display `~` in the window and are labeled in chat.
- Ordered and deferred/completed errands appear in the window, eight per page. New errands default to character-only; toggle to account-wide from the window. Quest-linked errands are always character-only. One versioned `ErrandMasterDB` SavedVariables table holds account errands, character errands, per-character observed locations, ID counters, and settings. Schema 1 migrates to schema 2 with discovery **off**, then to schema 3 with default wheel slots; unknown newer schemas are refused instead of silently rewritten.
- Up to 200 visible errands and 200 observed locations per character; route calculations run on explicit actions, map changes and quest/zone events, not continuously. Map display caps its own markers at 120 and never deletes unrelated pins. Same-map nearest-neighbor is a straight-line approximation, not a path or travel-time optimizer. Different-map/unmatched errands are deferred and never passed to the navigation adapter. Manual order disables optimization until re-enabled.
- TomTom integration is optional and checked at use time. Only the returned handle from ErrandMaster's own waypoint is removed; no unrelated TomTom waypoint is touched. Without TomTom, `/em next`, the window and the native world-map overlay show available destinations and coordinates. Native world-map drawing is an optional display adapter, not guaranteed client-side until game-tested.

## API decisions and fallback behavior

| Feature | API used | If unavailable/secret/unsupported |
| --- | --- | --- |
| Player position | `C_Map.GetBestMapForUnit("player")`, `C_Map.GetPlayerMapPosition(mapID,"player")`, vector `GetXY()`, `issecretvalue` guard | With no map, defer every errand. With a map but no position, manually located errands remain in manual order; no observed candidate can be selected reliably. |
| Map size | `C_Map.GetMapWorldSize(uiMapID)` (beta-extracted docs say width/height in yards) | No yard estimates; normalized same-map distances only. Never present a straight line as a walking path. |
| Active quest POIs | `C_QuestLog.GetQuestsOnMap`, `GetLogIndexForQuestID`, `GetInfo`, `QUEST_LOG_UPDATE` | No quest selector or inferred objectives without validated active quest map data. Quest errands lose routing when the current-map POI disappears. |
| Map display/click | Native `WorldMapFrame` `AddDataProvider`, `GetCanvas`, `GetMapID`, `AddCanvasClickHandler`, optional `OpenWorldMap`/`ToggleWorldMap` | No map overlay if canvas/handler unavailable; main errand window and coordinate navigation still work. Shift-click adds only after validated coordinates, out of combat. |
| Wheel spell/macro metadata | `C_Spell.GetSpellInfo`, `C_Macro.GetMacroName` when available | Show a generic numeric label if metadata is unavailable. This is selection/preview only; no protected action is invoked. |
| Character identity | `UnitFullName`, fallback `UnitName` + `GetRealmName` | Defer initialization to `PLAYER_LOGIN` if identity is not yet known; refuse to create a character bucket without an identity. |
| Storage | Native `## SavedVariables` global, `ADDON_LOADED` | If the client fails to restore saved data, tasks will not persist; no external cloud API or fabricated fallback. Test actual `/reload` and restart. |
| Navigation | Optional `TomTom:AddWaypoint` / `TomTom:RemoveWaypoint` (`source`, `title`, nonpersistent) | Still show coordinates in chat/window. No external service required for the MVP. |
| Native service observation | `MERCHANT_SHOW`, `MAIL_SHOW`, `AUCTION_HOUSE_SHOW`, `CanMerchantRepair`, `InCombatLockdown`, player position | No automatic location capture; use manually entered errand coordinates. If a service is observed, the saved coordinate is where the player stood, **not** the NPC's location. First-run off. |
| Guard/gossip POI | `C_GossipInfo.GetPoiForUiMapID`, `C_GossipInfo.GetPoiInfo`, POI vector `GetXY` | `/em poi` refuses cleanly; manually enter the destination. A POI does not encode a trustworthy service category by itself. |
| Wheel binding | Auto-loaded `Bindings.xml`, `GetBindingAction`, `GetBindingKey`, `SetBinding`, `SaveBindings`, `GetCurrentBindingSet`; frame keyboard input out of combat | If direct capture is restricted/unavailable, bind **Open ErrandMaster selection wheel** in WoW's own Key Bindings → AddOns, or use `/em wheel`. Conflicting existing bindings are not overwritten. |
| Wheel input/cursor | `GetCursorPosition`, frame `OnUpdate`/`OnMouseDown`, `UISpecialFrames`, `SetCursor` with bundled transparent BLP | Missing cursor data/combat state refuses opening; missing `SetCursor` leaves the visible cursor and keeps click selection usable. The wheel never simulates a player click or invokes protected gameplay. |
| Event/UI | `CreateFrame`, `ADDON_LOADED`, `PLAYER_LOGIN`, `PLAYER_ENTERING_WORLD`, `ZONE_CHANGED_NEW_AREA`, standard Blizzard templates | Core Lua remains separately testable; a missing UI template or changed API requires an in-client compatibility fix before distribution. |
| Equipment/inventory/trainer data | **Not used in v0.4.0** | Manual errands only. Do not infer NPC services, trainer offerings, or repair needs from unverified data. |
| Compact tracker / hold-release | **Not used in v0.4.0** | Main window and click-to-confirm wheel remain available. |

**No additional external web API is needed for this source version.** TomTom is the only optional addon API. WoW's native addon APIs expose a selected gossip POI or a player's position at an observed service, **not an exhaustive callable registry of every NPC, service, exact position, faction restriction or travel connection**. We cannot truthfully build an automatic complete service catalog from these signals. A future curated data pack would need source/version/license review, with explicit provenance and reachability rules; simply calling the Blizzard Developer web API does not supply a known NPC-location catalog. An external routing service is not necessary for same-map straight-line order. No out-of-game web API is contacted by the addon.

## Known restrictions

Forever has a Retail-derived API and secret-value/combat rules, not the Classic Era API. This code avoids protected gameplay actions, movement, item use, and combat-state analysis. Binding changes use the native restricted API **only out of combat and in response to a player keypress**; the normal Blizzard binding UI is the fallback. `16001`, map/quest API contracts and POI signatures come from nearby beta development references, **not a live probe of build 70374**. The addon refuses protected/unavailable values where checked. SavedVariables may vary across beta builds; do not claim persistence until testing the actual client. Same-map routing does not prove accessibility, faction availability, route length or travel time. Location capture is disabled in combat; no NPC IDs are inferred from the target. The window has no drag-position/scale persistence. No sound, compact tracker, smart suggestions, comprehensive NPC database or hold-to-release keybind yet. Wheel spell/macro entries cannot perform protected actions.

## Developer tests

From the project root, install `lupa` in an isolated local target (Python 3 available):

```sh
python3 -m pip install --target .testdeps lupa
python3 tests/run_tests.py
```

`run_tests.py` checks TOC file presence/order, Bindings.xml syntax/action, the uncompressed transparent BLP structure, and Lua 5.1 parsing. It runs core storage/migration, active quest POI validation, same-map yard calculations, protected-value refusal, wheel slot/binding interaction, world-map overlay ownership/shift-click/quest paging, and mock WoW boot/UI tests. `lupa` is only a developer dependency; do not package `.testdeps`. Mocks **do not prove** real UI layout, cursor rendering, map markers, keybinding persistence, client API compatibility, actual POI event timing, or SavedVariables persistence.

In-client checklist on **1.60.1.70374**: install the candidate and confirm interface number; preview the wheel at center/edge, cursor restoration, click/cancel/combat; assign category/spell/macro slots and confirm spells/macros only report selection; verify named spell/icon and macro-ID fallback; bind/reload on both characters; open map before the native map has loaded, verify route/service markers and map paging; Shift-left-click and rename a marker; add an active quest with POI, move quest progress/map and confirm the route defers it; verify map-world-size yard estimates are labeled direct and missing-size fallback works; check ultrawide map placement and click passthrough; save/reload/full restart and multiple scopes; opt-in service and gossip POI discovery; TomTom ownership; invalid/secret values, unavailable map data and combat; inspect Lua errors. Preserve private account files and credentials.

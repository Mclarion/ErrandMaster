# ErrandMaster – Smart Route Planner

**v0.6.4-test1 volatile feedback build.** See `docs/TEST-STATUS.md` for the verified installation state; offline checks do not verify in-game behavior.

An early WoW: Forever addon. **This volatile candidate may be installed for a user-led test after guarded readback; its behavior is not verified in-game.** It stores personal errands, player-set map markers and selected active quests. The candidate defaults to an **observed-ground-trail graph**: no recorded connection means **unknown walking route**, never a fabricated straight-line path. `/em walking off` explicitly switches to labeled direct-distance estimates. Trail recording is off until `/em trails on`; map-level suggestions are coarse preferences, not terrain or safety guarantees. It includes opt-in player-discovered service locations, game-supplied quest waypoints, explicitly registered in-game gossip POIs, and a click-to-confirm radial selection wheel. It does **not** automate movement, interactions, combat, or purchases.

## Install and verify in game

1. Install the separate **QuestieDB Forever** addon (contract 4, interface 16001) and enable it for the same character before ErrandMaster; ErrandMaster's required `QuestieDB` dependency will prevent loading without it. Copy this `ErrandMaster` directory (excluding `.testdeps`, `.venv`, `tests`, `tools`, and `.gitignore`) to the **Forever** client `Interface/AddOns/ErrandMaster`, not Retail or Classic Era. Include `Bindings.xml` and all `Textures/*.blp` wheel assets. The beta path observed in September 2026 was `World of Warcraft/_classic_beta_/Interface/AddOns/ErrandMaster`.
2. The Forever Beta `WowB.exe` file version was read remotely as **1.60.1.70425**; interface `16001` is metadata until confirmed inside the client. Confirm the installed test build and readback in `docs/TEST-STATUS.md`; a source-only icon is not necessarily installed. All client behavior needs in-game testing. Use `/dump select(2, GetBuildInfo())` for the build and `/dump select(4, GetBuildInfo())` for the interface.
3. Enable the addon on the character selection AddOns screen and log in. If initialization fails, check chat and the game's Lua error display. Try `/em help`, `/em add`, then add an errand, `/em route`, `/em next`, and `/reload`.
4. Confirm an errand survives `/reload`, logout/login, and a full restart on the actual installed build. Persistence is unverified outside a Lua mock.

## Current features

- `/em` opens/closes the window; `/em add` focuses the name input. The window supports add, edit, delete, complete/reopen, move up/down, selected scope toggle, and current-position capture. Blank location fields create an unlocated task. Coordinates entered in the UI are **percent** (0–100); stored coordinates are normalized (0–1). NPC candidates come from the separate runtime QuestieDB Forever dependency; no records are copied into the addon or SavedVariables.
- `/em route` lists the first ten stops supported by the selected mode and a count of deferred/unknown errands; `/em optimize` enables automatic ordering; `/em next` reports the active destination and optionally creates a TomTom waypoint. `/em walking on|off` selects observed-walk routing (default) or **direct estimates**; `/em walking status` reports the selected mode. `/em trails on|off` explicitly controls per-character ground-trail observation (off by default); `/em trails status` reports capacity and `/em trails clear` requires a second confirmation before deleting the current character's observations. `/em settings` opens the AddOns settings page (a standalone fallback if unavailable); `/em debug` toggles diagnostics; `/em help` lists commands.
- **NPC search (runtime QuestieDB Forever):** `/em npcs` shows nearby service spawn candidates on your current map; `/em npcs bank|repair|vendor|trainer|auction|flight|innkeeper|class|profession` filters by service, `/em npcs class mage` and `/em npcs profession alchemy` filter trainer specialties with positive QuestieDB subtitle evidence, and `/em npcs find <name or subtitle>` searches names/specialties. `/em npcs near bank` ranks candidates by direct map proximity; `/em npc <ID>` inspects candidates, and `/em npc add <ID>` queues one for route recalculation. The window **NPCs** button lists nearby candidates in chat. Broad trainer entries without class/profession evidence do not count as specialized trainers. The NPC source and classification depend on a compatible provider; spawns may be phased, outdated, or absent on build 70425, and do not prove walkability.
- **Radial selection:** Open **Settings → AddOns → ErrandMaster** (or `/em settings`), then **Bind wheel** out of combat; if Forever lacks that Settings API, use the standalone fallback. The minimap icon opens the wheel on left click, Targets on right click, Settings on middle click; drag the icon around the rim. `Bindings.xml` also exposes the action under WoW's AddOns Key Bindings. `/em wheel` opens the wheel. Service slots show a nearest NPC candidate and a labeled **direct** estimate when evidence exists; clicking a service queues it. A preview slot never casts or uses items. The wheel scales with entry count, clamps to the screen and cancels on Escape or combat. Client rendering remains unverified.
- **Wheel art calibration:** The exact Forever beta texture-rotation direction has not been measured in-client. If colored slices appear opposite their icons, use **Flip pie art** in AddOns Settings and reopen the wheel. This changes artwork, not selection.
- **Icon-pack menu candidate:** Fresh wheels use the supplied catalog's category palette: blue Bank, purple Auction House, red Repair, green Vendor, amber Mailbox, blue Trainer, gold Travel, magenta Custom, plus gold Quests, teal Skills and copper Items. Forty-three standalone wheel PNGs across the supplied art revisions and thirteen class PNGs were converted into runtime art. Back, Cross, Travel, Flight Master, Portal, Boat, Hearthstone, Settings, waypoint Go, quest markers, lock controls, Mailbox, General Goods, Profession Vendor/Trainer, and dedicated Alchemy, Blacksmithing, Cooking, Enchanting, Engineering, First Aid, Fishing and Herbalism trainer/vendor art use supplied icons; `Rouge.png` maps to Rogue without renaming the source. The AddOns, minimap and window emblem is a provisional compass crop from the `All.png` catalog, not a separately supplied logo. Opening a submenu materializes it beside the chosen section and keeps earlier tiers visible with pre-blurred icons, dimmed labels and connectors; the Back icon returns one tier, while the center Cross closes on click and serves as an edit-mode drag handle. This visual hierarchy is offline-tested, not verified in the game. Vendor → Profession Vendor → character-relevant profession vendors is three tiers deep; Food, Reagents, Ammo and General Goods remain immediate Vendor choices. Class Trainer uses the player's class icon; Trainer also offers Profession and Weapon choices; Travel has Flight/Portal/Boat/Hearthstone plus Waypoint and Favorites; Custom has New/Saved Errands and Settings. Active Quests lists validated POIs on the current map. Skills and Items can hold matching drag-and-drop previews, as can the top layer. **Add missing sections** in AddOns settings appends categories to older edited wheels without replacing their slots. Travel → Favorites supports Add Coordinates, Current Favorites and Remove Favorite; removing a star retains its target. A current favorite can be made active but does not cast or travel. Portal/Boat routing still needs verified destination data, and Hearthstone use still needs a separately validated secure in-client action; those entries report their limit instead of inventing a route or using an item.
- **Wheel edit mode:** Click **Edit** on the wheel. Edit pins it open while dragging from bags; the separate **Pin** control also keeps it open. Drag the center to move the wheel and save its position, drag slots to reorder, or drag a slot outside the ring to remove it. Drop an item, spell, or macro cursor payload on the wheel to add a **preview-only** slot. Right-click a slot or use **Color** to cycle its category color. Click **Lock** when finished. Existing folders still open as submenus. All editing is out of combat. These interactions need live-client verification. **Slots never cast, use items, execute macros, or call third-party addon code.**
- **Targets:** Opens on first login at the left side by default. **Targets** in the main window, `/em list`, or minimap right-click toggles it; position and visibility persist. The movable panel lists numbered route stops, then deferred/unknown targets and completed ones. **Go** makes a target active and asks optional TomTom for an owned same-map arrow; **Done/Reopen**, **Remove**, **Up**, **Down** and **Fav/Unfav** work on each row. Favorites persist with the errand; completed favorites remain marked but appear in the wheel only after reopening. Manual ordering disables route optimization until re-enabled in Settings. Matching quest turn-ins or nearby service/NPC interactions complete the active target, but ambiguous unlocated errands require manual Done. A TomTom arrow does not prove a traversable path. ErrandMaster neither integrates with nor modifies RestedXP; check placement in-client.
- **Movement and neighboring zones:** While errands are active, a guarded position sample every half-second refreshes the route after about 50 yards, a map change, or a valid post-taxi landing sample. With native map-world projection available, a deferred service errand can show a candidate in a nearby sibling zone within 2,000 direct yards. It stays deferred and says **route unknown**; a border crossing is not inferred from distance.
- **Profession and class filters:** Class-trainer previews use the player's class. In AddOns Settings choose two main professions from dropdowns, check Cooking/Fishing/First Aid, or restore native detection; manual picks are character-specific and override native detection. In both Vendor and Trainer wheels, Cooking, First Aid and Fishing are always shown; when no primary profession is known or configured, all nine primary professions appear. Profession-trainer matches need QuestieDB subtitle evidence; absent evidence is not proof of availability.
- **Flight advice:** At an open taxi map only, the panel can suggest a node reported **reachable by that flight master** when its name exactly matches an already-queued destination map's name. The player must choose it in Blizzard's taxi UI; post-flight walking remains unknown until evidence is available. There is no persistent flight-edge graph, automatic flight click, or unverified taxi-map marker.
- **World map:** `/em map` or **Map destinations** opens the native world map with ErrandMaster-owned, numbered markers: green for fully observed segments, violet `P` for partial segments with unknown connectors, gray `U` for unknown walking paths, amber for explicit direct-estimate mode, blue `S` for observed services. A coincident visible small native icon can receive only our superscript number; that icon is never moved/hidden. This needs client verification. **Shift-left-click** adds a character-scoped map errand. A paged map-quest list and `/em quest <ID>` select only a validated active quest POI or a game-provided next waypoint on that map. Saving a quest does not save a permanent objective coordinate: if native position disappears, the errand is deferred. Native waypoints are contextual and **not** an NPC-location dataset. No cross-map/floor walking connection is invented.
- **Waypoint and coordinate favorites:** In Travel → Waypoint, **Pin** opens the map; left-click a location to place an ErrandMaster-owned character waypoint. **Select Current** activates the saved waypoint, or copies an available Blizzard waypoint into an owned target without changing Blizzard's pin. In Travel → Favorites, **Add Coordinates** accepts `Name; map ID; X; Y`, for example `Camp; 1412; 52.3; 48.9`. X and Y are percentages from 0 to 100 with a decimal point; malformed input displays this example and saves nothing. **Current Favorites** lists open starred targets, and **Remove Favorite** unstars one without deleting its errand. These map points are not proven walking routes.
- **NPC map pins:** the overlay displays up to 20 QuestieDB candidate service spawns as teal `N` markers, ranked by direct proximity when the displayed map matches the player's map. These are not guaranteed spawns or navigable endpoints; use `/em npc <ID>` to inspect them.
- **Observed routing (candidate only):** `/em trails on` opts the current character into ground-movement sampling every two seconds, retaining at most 400 nodes/1,200 directed edges per character. At capacity, recording stops and warns; it never silently deletes old evidence, and further recording requires a deliberate clear. Flying, taxi, swimming, vehicle motion, combat, jumps, and missing/secret APIs create no edges. UI map ID, world-map ID and world height separate stacked areas; native floor is unknown (`0`), not inferred from a 2D map. A bounded directed graph search reuses validated adjacency and shortest-path results across route candidates, weighing observed yards and coarse native suggested map-level penalties. A nearby unobserved endpoint is shown as a **partial segment** with an unverified connector, never a verified walk to that stop or a TomTom navigation waypoint. Disconnected paths remain **unknown**. No reverse traversal, terrain navmesh, cross-floor stair, safe ground, or NPC spawn is invented. `/em walking off` explicitly enables straight-line estimates. Only mocks have exercised this; game-managed disk persistence needs `/reload`/normal logout and a live test.
- **Route algorithm:** each recalculation runs directed Dijkstra over the bounded observed trail graph, compares candidate NPC spawns by reachable segment cost, and chooses the next supported stop greedily; errands sharing one candidate can share that stop. Direct mode compares same-map geometric distance instead. This is not a globally optimal traveling-salesperson tour, bridge/transport graph, terrain navmesh, or guarantee that the final connector is traversable. Adding a wheel option, NPC ID, or other errand refreshes the route. Cross-map travel is deferred rather than guessed.
- The wheel keeps the normal game cursor, including native bag-item drags. Its high-resolution annular slices scale up to 24 slots and use subdued category colors; edit mode cycles each category's color. Activating a target sets an ErrandMaster-owned optional TomTom arrow to its same-map coordinates, if available. **Clear pin** removes only that handle and pauses automatic re-creation until Go or `/em next`. The arrow is a direction, not a proven walking path. Art rotation, layout, cursor and drag behavior still require a game-client check.
- **Opt-in discovery:** `/em discover on` or the window button records the player's **approximate position** when native merchant, mail, auction, bank, or trainer interfaces open. When `UnitName("npc")` provides a safe name, the label combines that name with its observed service (e.g. `Bailor — Bank`); otherwise it says `Observed …`. An anonymous observation is never renamed to a later NPC without identity proof; both can be retained at the same position, and an equally close named observation is preferred. Bank observation additionally requires `C_Bank.AreAnyBankTypesViewable()`. A nonprofession trainer is class-labeled only when the trainer NPC's native class token matches the player's **and** trainer services exist; otherwise it is not class-routed. Profession trainers remain a separate category. A merchant with a validated projectile item is also labeled **Ammo Vendor**; this does not guarantee bullets rather than arrows. `CanMerchantRepair()` must return true for Repair. Service discovery remains **off by default**, including on migration; `/em discover off` stops it. Exact beta-client event/API behavior awaits live verification.
- **Game POIs:** after a player obtains a marker through in-game gossip, `/em poi repair` (or another explicitly chosen category, such as `bank`, `mailbox`, `auction house`, `vendor`) attempts to save the map coordinate returned by `C_GossipInfo.GetPoiForUiMapID` and `GetPoiInfo`. The addon **does not classify the POI**; the category is the player's assertion. This explicit command works with passive discovery off. No marker/API, protected value, or invalid coordinates means no record. The POI name is a map label, not a verified NPC identity.
- `/em locations` lists the first ten observed locations with IDs, coordinates and precision; `/em forget loc-<number>` removes one from the current character's registry. Records are character-only. NPC IDs and spawn candidates come from QuestieDB Forever at runtime; the addon does not bundle the provider's catalog. Quick-queued errands compare same-map provider candidates and approximate observed service positions, labeling their source and uncertainty. A generic Vendor can match catalog vendors and observed vendor subtypes; Ammo, Reagent, Food and profession-specific vendor filters require provider subtitle evidence or a matching player observation. A Class Trainer matches only the current player's class. Without a known coordinate the errand stays deferred, never falsely points to an NPC. Editing an automatic errand's name makes it a manual override. Directly entered coordinates take precedence. Approximate locations display `~` in the window and are labeled in chat.
- Ordered and deferred/completed errands appear in the window, eight per page. New errands default to character-only; quest-linked errands are always character-only. `ErrandMasterDB` holds errands, per-character observed service locations and walk trails, ID counters, and settings. Schema 5 adds bounded per-character trail nodes/edges, defaults passive trail observation **off** even during migration, and defaults observed routing on. Earlier schema migrations preserve errands/wheel settings; unknown newer schemas are refused rather than reset. Persisted movement history is local game-managed SavedVariables, not uploaded by the addon.
- Up to 200 visible errands and 200 observed service locations per character; the graph accepts at most 400 observed nodes/1,200 edges. Routing refreshes on UI commands, map/quest/zone events and eligible 50-yard movement or landing samples; opt-in trail recording remains a separate two-second sampler. Map display caps its own markers at 120 and never deletes unrelated pins. Direct-estimate mode is explicitly labeled; graph mode does not navigate unknown connections. Different-map/unmatched errands are deferred and never passed to TomTom.
- TomTom integration is optional and checked at use time. Only the returned handle from ErrandMaster's own waypoint is removed; no unrelated TomTom waypoint is touched. Without TomTom, `/em next`, the window and the native world-map overlay show available destinations and coordinates. Native world-map drawing is an optional display adapter, not guaranteed client-side until game-tested.

## API decisions and fallback behavior

| Feature | API used | If unavailable/secret/unsupported |
| --- | --- | --- |
| Player position | `C_Map.GetBestMapForUnit("player")`, `C_Map.GetPlayerMapPosition(mapID,"player")`, vector `GetXY()`, `issecretvalue` guard | With no map, defer every errand. With a map but no position, manually located errands remain in manual order; no observed candidate can be selected reliably. |
| Map size | `C_Map.GetMapWorldSize(uiMapID)` (beta-extracted docs say width/height in yards) | No yard estimates; normalized same-map distances only. Never present a straight line as a walking path. |
| Active quest POIs/next waypoint | `C_QuestLog.GetQuestsOnMap`, `GetLogIndexForQuestID`, `GetInfo`, `GetNextWaypoint`, `GetNextWaypointForMap`, `GetNextWaypointText`, `QUEST_LOG_UPDATE` | A validated active quest can use the game-provided same-map POI or current next waypoint; no stale coordinate is retained when native data disappears. Not an NPC spawn catalog. |
| Walk evidence/level preference | `UnitPosition`, `C_Map.GetBestMapForUnit`, `GetPlayerMapPosition`, optional `GetMapLevels`, `UnitLevel`, movement flags/speed, `GetTime` | Opt-in, character-scoped observations only; missing/secret/implausible samples create no traversable edge. Suggested map level is a coarse penalty, never a safety guarantee. No terrain navmesh or inferred floor links. |
| Map display/click | Native `WorldMapFrame` `AddDataProvider`, `GetCanvas`, `GetMapID`, `AddCanvasClickHandler`, optional `OpenWorldMap`/`ToggleWorldMap` | No map overlay if canvas/handler unavailable; main errand window and coordinate navigation still work. Shift-click adds only after validated coordinates, out of combat. |
| Wheel spell/macro metadata | `C_Spell.GetSpellInfo`, `C_Macro.GetMacroName` when available | Show a generic numeric label if metadata is unavailable. This is selection/preview only; no protected action is invoked. |
| Character identity | `UnitFullName`, fallback `UnitName` + `GetRealmName` | Defer initialization to `PLAYER_LOGIN` if identity is not yet known; refuse to create a character bucket without an identity. |
| Storage | Native `## SavedVariables` global, `ADDON_LOADED` | If the client fails to restore saved data, tasks will not persist; no external cloud API or fabricated fallback. Test actual `/reload` and restart. |
| Navigation | Optional `TomTom:AddWaypoint` / `TomTom:RemoveWaypoint` (`source`, `title`, nonpersistent) | Still show coordinates in chat/window. No external service required for the MVP. |
| Native service observation | `MERCHANT_SHOW`, `MAIL_SHOW`, `AUCTION_HOUSE_SHOW`, `BANKFRAME_OPENED`, `TRAINER_SHOW`, `UnitName("npc")`, `UnitClass("player")`, `IsTradeskillTrainer`, `C_Bank.AreAnyBankTypesViewable`, `CanMerchantRepair`, optional merchant item/link/type lookup, player position | If unavailable or protected, omit that classification/name. Captured coordinate is where the player stood, **not** the NPC's location. First-run off. |
| Guard/gossip POI | `C_GossipInfo.GetPoiForUiMapID`, `C_GossipInfo.GetPoiInfo`, POI vector `GetXY` | `/em poi` refuses cleanly; manually enter the destination. A POI does not encode a trustworthy service category by itself. |
| Wheel binding | Auto-loaded `Bindings.xml`, `GetBindingAction`, `GetBindingKey`, `SetBinding`, `SaveBindings`, `GetCurrentBindingSet`; frame keyboard/mouse input out of combat | If direct capture is restricted/unavailable, bind **Open ErrandMaster selection wheel** in WoW's own Key Bindings → AddOns, or use `/em wheel`. Conflicting existing bindings are not overwritten. |
| Wheel input/cursor | `GetCursorPosition`, frame `OnUpdate`/`OnMouseDown`, `UISpecialFrames`, native cursor drops | Missing cursor data/combat state refuses opening; the visible game cursor remains usable for bags. The wheel never simulates a player click or invokes protected gameplay. |
| Event/UI | `CreateFrame`, `ADDON_LOADED`, `PLAYER_LOGIN`, `PLAYER_ENTERING_WORLD`, `ZONE_CHANGED_NEW_AREA`, standard Blizzard templates | Core Lua remains separately testable; a missing UI template or changed API requires an in-client compatibility fix before distribution. |
| Equipment/inventory/trainer data | Trainer type and merchant projectile stock only; no equipment/bag inspection or trainer offerings | No repair need, bullet supply, or item-buy recommendations are inferred. A projectile vendor may sell arrows rather than bullets. |
| Targets panel / hold-release | Movable tracker with active, completed and deferred rows; hold-release is not implemented | Main window, `/em list`, and click-to-confirm wheel remain available. |

**No additional external web API is needed for this source version.** QuestieDB Forever is a required runtime addon; TomTom is optional. WoW's native addon APIs expose a selected gossip POI or a player's position at an observed service, **not an exhaustive callable registry of every NPC, service, exact position, faction restriction or travel connection**. We cannot truthfully build an automatic complete service catalog from these signals. A future curated data pack would need source/version/license review, with explicit provenance and reachability rules; simply calling the Blizzard Developer web API does not supply a known NPC-location catalog. An external routing service is not necessary for same-map straight-line order. No out-of-game web API is contacted by the addon.

## Known restrictions

The AddOns page's **Advanced wheel layout** button opens optional controls for radius, scale, theme, folders and manual entries; routine edits happen on the wheel. Automatic completion requires a matched service event and, where a candidate NPC ID is known, that NPC's identity. A generic gossip conversation does not complete a service errand.

Forever has a Retail-derived API and secret-value/combat rules, not the Classic Era API. This code avoids protected gameplay actions, movement, item use, and combat-state analysis. Binding changes use native restricted APIs only out of combat and in response to a player key or mouse button; WoW Key Bindings is the fallback. `16001` and beta API contracts still require live verification. SavedVariables may vary across builds; the new window positions, wheel artwork and mouse capture have only offline tests. Same-map routing does not prove accessibility or safety. No sound, bundled NPC database or hold-to-release keybind yet. Spell/macro entries are previews, not protected actions.

## Developer tests

From the project root, install `lupa` in an isolated local target (Python 3 available):

```sh
python3 -m pip install --target .testdeps lupa
python3 tests/run_tests.py
```

`run_tests.py` checks TOC load order, Bindings.xml, icon and antialiased BLP structure, deterministic wheel sectors/trim/map hub, and Lua 5.1 syntax. It exercises storage/migration, routing, wheel editing and pinning, target completion, AddOns settings registration, and mock WoW boot/UI paths. `lupa` is only a developer dependency; do not package `.testdeps`. The Bank and class images were converted from the project's Vaultkeeper assets with `tools/convert_icon.py`; game rendering remains unverified. Mocks **do not prove** actual layout, textures, map markers, keybinding persistence, client API compatibility, event timing, or SavedVariables persistence.

Before any client test, follow the offline and live acceptance gates in [`docs/READINESS.md`](docs/READINESS.md). `tests/benchmark_walk.py` is a manual 400-node/200-stop Lua 5.1 stress probe; timing depends on hardware and does not establish in-client responsiveness.

In-client checklist on **1.60.1.70425**: confirm the installed addon loads and its interface number; preview the wheel at center/edge, cursor restoration, click/cancel/combat; assign category/spell/macro slots and confirm spells/macros only report selection; verify named spell/icon and macro-ID fallback; bind/reload on both characters; open map before the native map has loaded, verify route/service markers and map paging; Shift-left-click and rename a marker; add an active quest with POI, move quest progress/map and confirm the route defers it; verify map-world-size yard estimates are labeled direct and missing-size fallback works; check ultrawide map placement and click passthrough; save/reload/full restart and multiple scopes; opt-in service and gossip POI discovery; TomTom ownership; invalid/secret values, unavailable map data and combat; inspect Lua errors. Preserve private account files and credentials.
